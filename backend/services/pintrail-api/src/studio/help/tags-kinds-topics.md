The Studio has four ways to say that artifacts belong together. They answer different questions, and most artifacts use several.

| | Answers | How many per artifact | Has its own page? | Example |
|---|---|---|---|---|
| **[Nesting](/studio/help/nesting)** | *Where is it? What is it part of?* | One parent | The parent is an artifact | *Green roof* inside *Integrative Learning Center* |
| **[Kind](/studio/help/kinds)** | *What sort of thing is it?* | Exactly one | No | `other` |
| **[Tags](/studio/help/tags)** | *What is it about?* | Any number | No | *stormwater*, *water* |
| **[Topics](/studio/help/topics)** | *What shared story does it belong to?* | Any number | Yes | *LEED certification* (*Gold, 2013*) |

And a fifth, for a different purpose: a **[trail](/studio/help/trails)** puts artifacts in **walking order**.

## Choosing, by example

> **Example:** A solar canopy over a parking lot. It stands on its own (no parent), it keeps kind `other` for this collection, it's about *solar* and *energy* (tags). If several canopies share one story, say a campus-wide solar program, link them all to a topic for it.

> **Example:** A battery system inside the heating plant. It's part of the plant (nest it inside), it keeps kind `other`, about *energy storage* (tag).

> **Example:** The six Valley Bike Share stations. Six separate places (six artifacts, each with its own pin), kind `other`, tagged *transportation*, all linked to the topic *Valley Bike Share*.

## Quick rules

- **Part of, in, or on something?** Nest it.
- **Kind for this collection?** Keep Other and use tags, following [#56](https://github.com/pintrail/pintrail/issues/56).
- **A theme someone might search for?** Add a tag.
- **Something worth explaining that many artifacts share?** Make a topic, and link them to it.
- **A route to walk?** Make a trail.
