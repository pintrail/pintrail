An artifact's **kind** is shown as a small grey label next to its name and is
used to colour markers on the [map](/studio/help/map).

**For the current collection, choose Other (`other`) and add descriptive tags.**
This follows [#56](https://github.com/pintrail/pintrail/issues/56): the kind/theme
design will be revisited after real data is available. Do not reclassify existing
records unless asked. Describe what something is in its name and description.

## The kinds

| Kind | Use it for | Examples |
|---|---|---|
| `building` | A whole building. | *Old Chapel*, *Central Heating Plant* |
| `room` | A space inside a building. | *ILC lobby*, *Room S331 teaching lab* |
| `artwork` | A mural, sculpture, or other piece of art. | *Student Union mural* |
| `installation` | Equipment or a feature of a site. | *Solar canopy*, *battery system*, *rain garden*, *bike rack*, *water bottle filler* |
| `rooftop` | A roof and what's on it. | *Green roof*, *rooftop solar* |
| `other` | Anything that fits none of these. | *A memorial bench*, *a campus tree* |

## Current collection example

> **Example:** For a *Battery energy storage system* inside the heating plant,
> keep kind `other`, nest it under the plant, and add the tag *energy storage*.

## New artifacts start as `other`

When you create an artifact you only give it a name and a place. It starts as
`other`; keep that value while adding its description and tags through **Edit**.

## When nothing fits

Use [tags](/studio/help/tags) such as *bench* or *tree*, reusing suggestions where
possible. For now the same Other-and-tags instruction applies even when a more
specific kind exists in the list above.

## Kinds versus tags

There is one kind and any number of tags per artifact. For this collection a
solar canopy stays `other` and gets tags such as *solar* and *energy*.
See [Kinds, tags, topics, or nesting?](/studio/help/tags-kinds-topics).
